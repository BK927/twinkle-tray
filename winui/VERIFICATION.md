# Windows x64 자동 검증 · 0.2.1

2026-09-29, Windows 11 Pro 10.0.26200 x64 환경에서 검사했습니다. Apple 디스플레이와 ARM64는 이번 실기기 검증 범위에서 제외했습니다. 빌드 성공이나 모의 장치 검사만으로 다른 Windows 버전·모니터 모델의 동작까지 검증됐다고 판단하지 않습니다.

## 통과한 검사

| 검사 | 결과 |
| --- | --- |
| 코어 | 46/46: 보정, 예약, 태양 이벤트, 설정, 가져오기, 프로필, 명령 파싱 등 |
| 앱 실행 중 동작 | 41/41: 실제 컨트롤러를 모의 장치로 실행; 자동 제어 상호작용 20개 포함 |
| 외부 명령 연결 | 11개 그룹: 목록, 선택, 증감, 범위 제한, 잘못된 요청 뒤 회복, 설정 및 OSD |
| 설정 페이지 | 11개 페이지 생성 |
| 업데이트 | 모의 HTTP로 채널 선택, 내려받기, 체크섬, 압축 해제, 외부 저장소 파일 거부; 임시 설치 폴더에서 교체와 실패 복구 |
| Windows 환경 | 잠금·미디어 상태 조회, 센서 목록 조회; 실제 조도 센서는 없고 Yoctopuce 응답은 로컬 시험 서버로 검사 |
| 초기 장치 인식 | 새 프로세스 3개에서 첫 검색부터 두 모니터의 DDC/CI·밝기·대비를 정상 인식 |
| 검사 도구의 복구 | DDC 모의 사례 9개, 감마 모의 사례 5개: 실패·취소·장치 교체·다른 화면 변경 시 중단과 복구 |

앱 실행 검사는 저장된 설정과 실제 장치를 사용하는 대신 `--smoke-test` 및 `--demo`의 별도 인스턴스를 사용합니다. 예약 시각·잠금·앱 전환·유휴·미디어 상태는 결정된 입력으로 주입하되, 실제 앱의 자동 제어 메서드를 호출합니다. 물리적인 절전이나 케이블 분리를 재현한 것은 아닙니다.

## 실제 모니터의 변경과 복원

| 모니터 | 밝기 | 대비 | 격리 및 복원 |
| --- | --- | --- | --- |
| LG ULTRAGEAR+ | 100 → 98 → 100 | 70 → 72 → 70 | 재조회 일치, 다른 화면 유지, 원값 복원 |
| AOC Q32V3WG5 | 100 → 98 → 100 | 50 → 52 → 50 | 재조회 일치, 다른 화면 유지, 원값 복원 |

변경 전 원래 원시 값과 연결 정보를 디스크에 기록했습니다. 일반 밝기·대비 API로 최대 2단계만 변경하고, DDC 값을 다시 읽어 확인한 뒤 정확한 원시 값으로 복원했습니다. 각 단계에서 다른 모니터의 밝기·대비가 유지되는지 확인했습니다. 입력·전원·절전·HDR 활성화는 변경하지 않았습니다. 장치가 보고한 값을 검증했으며 광도계 측정이나 깜빡임 육안 검증은 아닙니다.

감마는 두 모니터에 각각 98% 요청을 보내 실제 보정 테이블의 변경을 확인했습니다. 변경 전 저장한 RGB 768개 원본 값이 모두 정확히 복원됐으며, 각 단계에서 다른 화면의 감마도 유지됐습니다. Windows에서 읽어 온 감마 테이블을 확인한 결과이고 실제 색 정확도나 HDR 동작 검증은 아닙니다.

첫 검사에서는 초기 LG 연결 상태가 달라 쓰기 전에 중단됐습니다. 후속 기록에서 Windows가 첫 조회에 성공을 반환하면서 무효 물리 핸들을 돌려주는 경우를 확인했고, 읽기 전용 탐지를 제한 횟수만큼 재시도하도록 수정했습니다. 무효 핸들은 해제하며 쓰기 명령 자체를 재시도하는 변경은 아닙니다.

## 발견해서 수정한 문제

- 같은 시각에 여러 예약이 있으면 도달할 목표와 적용할 값이 달랐던 보간 오류.
- 모니터별 예약 ID의 대소문자와 일광절약시간의 존재하지 않는 시각 처리.
- 예약·프로필 전환 도중 유휴·일시정지·잠금으로 중단되면 목표 밝기를 잃는 문제.
- 일반 슬라이더뿐 아니라 원시 VCP·감마 명령의 수동 값도 재개·유휴 복원 후 유지되도록 수정. 수동 프로필과 명시적인 현재 예약 적용도 이전 자동 목표를 취소하도록 수정.
- 빠른 일시정지·재개에서 취소 중인 이전 전환이 새 전환을 막는 문제.
- 초기 조회의 무효 물리 핸들 처리 및 HDR 조회 실패와 확인된 SDR 상태 구분.

## 반복 실행

저장소 루트의 PowerShell에서 실행합니다.

```powershell
dotnet run --project ./winui/TwinkleTray.Core.Tests -c Release
./winui/test-app.ps1 -AppPath ./winui/artifacts/win-x64/TwinkleTray.WinUI.exe
dotnet run --project ./winui/TwinkleTray.Hardware/Diagnostics -c Release -- --read-only --features --environment
```

실물 값을 바꾸는 검사는 별도의 명시적 옵션을 요구합니다. 재실행 시 기존 밝기 관리 앱을 종료하고 새 절대 경로의 보고서 파일을 지정해야 합니다. 원값 복원에 실패하거나 연결·다른 화면 값이 달라지면 다음 변경을 중단합니다. 옵션과 복구 기록 구조는 [하드웨어 문서](TwinkleTray.Hardware/README.md)에 있습니다. 이 경로는 CI에서 실행하지 않으며 CI는 모의 장치 복구 검사만 수행합니다.

## 남은 검증

- 실제 화면의 깜빡임·색감·체감 밝기, 다양한 DPI·고대비·접근성.
- Windows 10, 노트북 WMI·덮개·전용 키, 실제 조도 센서.
- HDR 활성화 후 SDR 밝기 변경, 전원·입력 전환, 실제 절전·재연결.
- 서명된 MSIX 설치·시작 등록과 실제 배포 서버를 거치는 업데이트·재시작 전체 흐름.

위 항목은 미검증이며 자동 검사의 통과 항목에 포함하지 않습니다.
